Two minutes, then you are done

Make the blessings arrive

Right now a guest can write a blessing, but it stops on their own phone. Two small steps and every message lands where you can read it.

      1 Turn on the blessings inbox The quick way — no account, no password, works in a couple of minutes
      1. Go to web3forms.com.
      2. Type the email address you want the blessings sent to, and press the button. It gives you an access key straight away. No account, no password.
      3. Open config.js and find:
        config.jsinbox: {
          accessKey: '{{INBOX_KEY}}',
      4. Paste your key in, in the quotes:
        becomesinbox: {
          accessKey: 'a1b2c3d4-....',
      5. Save. Reload the page — the amber bar at the top turns green and says blessings are being emailed to you.

      That is it. Every blessing a guest seals now arrives in that inbox, with their name, their message, and their contact details so you can thank them. Free for 250 blessings, which is far more than a wedding needs.

      2 Turn on the private panel The full version — a locked database, search, filters and CSV export

      Step 1 already gets you every message. This step gives you the private admin.html page instead, where you can search, filter, mark as read, hide, delete and export everything as a spreadsheet.

      2a — Get the second key

      In your Supabase project, go to Project Settings → API. Copy the one labelled anon public. It is a long string that begins eyJ and ends in a signature. That is the one you want — not the service_role key.

      then in config.jssupabase: {
        url: 'https://cumgwfrjilghykgszblt.supabase.co',
        anonKey: 'eyJhbGciOi...',
      },

      Your project URL is already filled in. Only the key is missing.

      The anon key is meant to sit in a public web page — it is the front door, not the key to the house. The database policy in step 2b is what actually locks the blessings. Seeing it in the HTML is normal and is not a mistake.

      2b — Make the table

      1. Open supabase-schema.sql in this folder.
      2. In Supabase, go to SQL Editor → New query.
      3. Copy the whole file in, press Run. It is safe to run twice.

      2c — Close the door

      1. Authentication → Providers → Email, and turn off Enable email signup.
      2. While that page is open, also check the site URL is https://cumgwfrjilghykgszblt.supabase.co.

      Do not skip 2c. With signup left on, anybody who finds the address could register themselves and read every blessing. This one line is what makes it private.

      2d — Make the three logins

      Authentication → Users → Add user, three times — once for you, once for Rose, once for Daniel. Use real addresses you can open, set passwords you will remember, and tick “Auto Confirm User” each time. Without that tick you cannot sign in.

      Then open admin.html and sign in.
